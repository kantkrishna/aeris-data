# Goal

Transition the AERIS multi-engine architecture from a simulated abstraction into a **live, fully integrated execution platform**.

The objective is to replace the mock executors with robust SDK implementations connecting to actual Snowflake and Databricks environments. Demonstrate secure credential injection, live payload execution, asynchronous status polling, and resilient error handling.

Just register the prompt. Do not create any code yet.

# Epics

## Epic 19 — Secure Credential & Secrets Management

**Deliverables**

* Define a `SecretsManager` interface to abstract credential retrieval.
* Implement secure credential retrieval for Snowflake (e.g., Key-Pair or user/password) and Databricks (e.g., PAT or OAuth).
* Ensure credentials are injected at runtime and never logged or hardcoded.

**Expected outcome:** The platform can authenticate securely to external engines without leaking secrets into environment variables or source control.

## Epic 20 — Snowflake Live Integration

**Deliverables**

* Implement the full `SnowflakeExecutor` using the official `snowflake-connector-python`.
* Handle connection instantiation, cursor management, and payload execution.
* Implement custom exception handling for network timeouts, warehouse suspension delays, and SQL syntax errors.

**Expected outcome:** AERIS can successfully execute live SQL payloads and retrieve operational metadata from a real Snowflake virtual warehouse.

## Epic 21 — Databricks Live Integration

**Deliverables**

* Implement the full `DatabricksExecutor` using the official `databricks-sdk` for Python.
* Develop logic to trigger an existing Databricks Job (e.g., via the Jobs API `run_now` endpoint).
* Implement asynchronous status polling to track the job from `PENDING` to `SUCCESS` or `FAILED`.
* Fetch and log standard error outputs if the job fails.

**Expected outcome:** AERIS can orchestrate Databricks clusters, trigger PySpark jobs, and reliably wait for their completion states.

## Epic 22 — Resiliency & Retry Logic

**Deliverables**

* Implement exponential backoff for transient API failures (e.g., HTTP 429 Too Many Requests or temporary network drops).
* Ensure long-running queries or jobs do not cause blocking timeouts in the main orchestrator thread.
* Map engine-specific SDK errors into standard AERIS platform exceptions.

**Expected outcome:** The platform handles external API unreliability gracefully without failing the overarching pipeline.

## Epic 23 — Live Integration Testing

**Deliverables**

* Create a dedicated `tests/integration/` test suite, separated from the deterministic unit tests.
* Write Pytest fixtures that establish live API connections using injected test-environment secrets.
* Implement end-to-end teardown logic (e.g., dropping test tables in Snowflake, canceling hanging test jobs in Databricks) to ensure idempotent test runs.

**Expected outcome:** AERIS maintains high confidence in its live engine connectivity without sacrificing the speed and isolation of its unit tests.

# Definition of Done

Demonstrate:

**AERIS Orchestrator → Secure Secrets Fetch → Live Snowflake Query OR Live Databricks Job → Resilient Polling → Standardized Output**

The platform must successfully authenticate, execute, and return actual metadata from both Snowflake and Databricks environments, proving production-readiness.
